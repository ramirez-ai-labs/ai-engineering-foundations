# 05 - Mini Projects

Small end-to-end projects that combine the earlier chapters. For each one, you should be able to identify the data structures underneath it, the algorithm driving it, and the AI concept it demonstrates.

## Simple Vector Search Demo

`ex01_simple_vector_search_demo.py` ranks four documents against a query vector using cosine similarity, which is the core of retrieval in a RAG system.

It combines:

- tuples and lists to hold vectors and results
- loops to compute dot products and vector lengths
- a sorted top-k list to rank results
- input validation that rejects mismatched dimensions, zero vectors, and a `top_k` below 1

### How To Run

From this folder:

```bash
python ex01_simple_vector_search_demo.py
python -m unittest -v
```

### What This Demo Simplifies

- embeddings are written by hand instead of generated by a model
- search scans every document instead of using an ANN index such as HNSW
- there is no persistence, chunking pipeline, or metadata filtering
- ranking uses cosine similarity only, with no re-ranker

### Practice Prompts

- change one document vector and predict how the ranking moves
- add a metadata field and filter on it before scoring
- compare the ranking from plain dot product with cosine similarity
- estimate how long an exact scan would take over 4,000,000 documents

Read [Embeddings and Vector Search](../../Java/04-ai-foundations/01-EmbeddingsAndVectorSearch.md) for the concepts behind this demo.

## Knowledge Graph BFS

`ex02_knowledge_graph_bfs.py` expands a query concept into every related concept within N hops of a small, directed AI-topic graph. Graph-based retrieval (such as GraphRAG) uses this step to pull in context that is logically connected but not necessarily close in embedding space.

It combines:

- a dict of edge lists as the adjacency structure, with named nodes and labeled edges
- the BFS from `01-data-structures/ex05_graph_dfs_and_bfs.py`, plus a hop limit
- a recorded path per node, so you can see why each concept was retrieved

### How To Run

From this folder:

```bash
python ex02_knowledge_graph_bfs.py
python -m unittest test_ex02_knowledge_graph_bfs -v
```

### What This Demo Simplifies

- the graph is hand-written and tiny; real knowledge graphs are extracted from documents and stored in a graph database
- edges are unweighted, so every relation counts as equally relevant
- there is no cap on neighbors per hop; a highly connected node can flood the LLM context

### Practice Prompts

- add a `relations` filter so the traversal follows only some edge types (for example, only `evaluated_by`)
- cap the number of neighbors expanded per node, and explain what that protects against
- treat edges as two-way, and predict which new nodes appear from `Embeddings`
