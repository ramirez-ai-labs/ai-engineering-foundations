# 05 - Mini Projects

This folder should contain small end-to-end projects that combine ideas from the earlier sections.

This chapter is where the repo's progression becomes concrete. Learners should be able to look at a mini-project and identify:

- the data structures underneath it
- the algorithms driving it
- the systems constraints shaping it
- the AI concept the project is demonstrating

A good mini-project in this repo should:

- reinforce one or two core CS ideas
- connect clearly to AI engineering work
- stay small enough for a learner to understand in one sitting
- avoid heavy scaffolding unless the scaffolding itself is part of the lesson

## Progression To AI Engineering

Mini-projects should make the dependency chain visible:

1. core CS foundations make the implementation understandable
2. systems concepts make the implementation operationally credible
3. AI foundations make the use case and tradeoffs intelligible

If a learner finishes a mini-project without seeing that chain, the project is missing part of its teaching value.

## Project Ideas

### 1. Search Service With Caching

Concepts:

- hash maps
- caching
- API design
- latency reduction

What a learner should build:

- a small search endpoint or command-line service
- a cache for repeated queries
- simple request and response logging

### 2. Rate-Limited API Wrapper

Concepts:

- queues
- rate limiting
- retries
- external service protection

What a learner should build:

- a wrapper around a mock AI endpoint
- a limiter that blocks or delays extra requests
- clear output showing allowed vs rejected requests

### 3. Simple Vector Search Demo

Concepts:

- arrays
- cosine similarity or dot product
- ranking
- retrieval intuition

What a learner should build:

- a tiny in-memory vector index
- a query vector
- ranked nearest results

Current file:

- `Ex01SimpleVectorSearchDemo.java`: exact-scan cosine-similarity demo with hand-written embeddings, plus a timing benchmark at 100/1k/10k vectors that shows where linear scan breaks and why ANN indexes exist

## Project Quality Bar

Mini-projects in this repo should include:

- a problem statement
- setup and run instructions
- a short architecture explanation
- beginner-readable code
- comments on what is intentionally simplified

## How To Run The Current Demos

From this folder:

```bash
javac *.java
java Ex01SimpleVectorSearchDemo
java Ex02KnowledgeGraphBFS
java AllTests
```

`AllTests` covers cosine similarity, top-k ranking, and input validation in the vector search, plus hop limits, discovery order, directed edges, and cycles in the knowledge graph BFS. See [01-data-structures/README.md](../01-data-structures/README.md#testing) for how the tests work.

What the vector search demo intentionally simplifies:

- embeddings are written directly in code instead of generated by a model
- the search scans every vector instead of using an ANN index
- there is no metadata filtering, chunking pipeline, or persistence layer
- ranking is only cosine similarity with no re-ranker
- it sorts every score and then takes the top k, which is O(n log n); the Python version keeps a running top-k list instead, which is O(n * k), and a heap gives O(n log k)

What the knowledge graph demo intentionally simplifies:

- the graph is hand-written and tiny; real knowledge graphs are extracted from documents and stored in a graph database
- edges are unweighted, so every relation counts as equally relevant
- there is no cap on neighbors per hop, so a highly connected node can flood the LLM context

## What To Avoid

- oversized frameworks for a tiny concept
- fake complexity that hides the main lesson
- production claims for demo-only code
- projects with no explanation of why they matter
